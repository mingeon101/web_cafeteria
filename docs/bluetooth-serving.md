# 현장 배식 · 새 아두이노 코드 연동

PC에서 HC-05/HC-06을 먼저 페어링한 뒤 웹의 **블루투스 연결**에서 장치 또는 해당 COM 포트를 선택합니다. UUID 입력은 없습니다. 통신 속도 기본값은 스케치의 `BT.begin(9600)`과 같은 9600bps입니다.

## 전송과 응답

밥 → 반찬 → 국 순서로 숫자를 **세 번 따로** 전송합니다. 내부 수량 배열은 밥·국·김치 순서이므로 전송 순서는 0→2→1입니다. 0회도 생략하지 않으며 알레르기로 차단된 메뉴는 기존 검사에서 0회로 정리한 뒤 전송합니다. 이름이나 JSON은 보내지 않습니다.

예: 밥 2회, 반찬 1회, 국 3회:

```js
write('2\n');
write('1\n');
write('3'); // 마지막 숫자 뒤에는 줄바꿈 없음
```

제공된 스케치의 `BT.parseInt()`는 숫자 뒤 구분자를 버퍼에 남깁니다. 세 번째 숫자 뒤에 LF가 남으면 배식 후 다음 loop에서 `BT.available()`가 참이 되어 `parseInt()` 시간 만료 후 0이 첫 값으로 들어갈 수 있습니다. 마지막 값에는 구분자를 보내지 않고 스케치의 Stream 타임아웃으로 숫자를 확정합니다. 기본 설정에서는 마지막 숫자 수신 후 약 1초가 걸릴 수 있습니다. 앞 두 구분자를 읽기 전에 타임아웃이 발생하지 않도록 세 쓰기를 직렬 실행하고 앞 두 쓰기 후 각각 300ms(0.3초) 대기합니다. 이 간격은 현재 스케치의 기본 1000ms 타임아웃보다 짧습니다. 스케치에서 타임아웃을 별도로 줄인 경우 전송 간격과 함께 조정해야 합니다.

장치는 수량 3개를 읽고 센서가 식판을 감지하면 다음을 송신합니다.

```text
배식을 시작합니다\r\n
배식을 완료했습니다\r\n
```

웹은 숫자 3개를 모두 전송한 즉시 진행 중 화면을 표시합니다. `배식을 시작합니다` 응답은 기다리지 않으며, 문구가 오거나 오지 않아도 흐름에 영향을 주지 않습니다. `배식을 완료했습니다` 응답만 확인하여 Firebase 완료 저장 후 마지막 화면으로 연결합니다. 기존 짧은 응답과 이전 자동 시퀀스 문구도 호환용으로 인식합니다. 전송 전 또는 작업이 없는 상태의 응답, 중복 완료, 초기화 로그는 완료 처리하지 않습니다. 분할 UTF-8/CRLF 입력을 처리합니다.

## 중복 방지와 저장

전송 중 초기화·수량 변경·다음 주문을 막습니다. 끊김 또는 일부 전송 실패 시 자동 재전송하지 않고 장치 확인이 필요합니다. 미확인 작업은 브라우저에 보관하여 새로고침 후 중복 배식을 막습니다. 장치 완료 후 저장 실패는 **저장만** 재시도합니다.

기존 학생 확인, 좌석 배정, 알레르기 검사, 급식시간 판정 및 배식 기록 경로는 유지합니다. 선주문은 processing → 장치 완료 응답 후 fulfilled로 변경합니다. `students/{uid}/serve/{key}/hardware`에 상태를 저장합니다. `stats` 트랜잭션으로 queueCount와 주문별 bluetoothCompleted 마커를 함께 갱신하므로 관리자용 Firebase 규칙에서 해당 읽기·쓰기가 허용되어야 합니다. 규칙을 공개하거나 변경하지 않습니다.

## 아두이노 배선 확인

제공된 스케치의 `SoftwareSerial BT(16,17)`은 보드에 따라 사용할 수 없습니다. **Mega/Mega 2560의 SoftwareSerial RX에는 16번 핀이 지원되지 않습니다.** 이 보드를 사용한다면 현재 모터와 충돌하지 않는 지원 RX(예: A8/62)로 스케치와 모듈 TX 배선을 함께 바꾸거나 하드웨어 시리얼을 사용해야 합니다. 웹 수정으로 이 핀 제한을 해결할 수 없습니다. 실제 보드·배선을 확인하기 전 하드웨어 동작을 보장하지 않습니다.

참고: [Arduino SoftwareSerial 지원 핀](https://docs.arduino.cc/learn/built-in-libraries/software-serial/), [Arduino AVR Stream.parseInt 구현](https://github.com/arduino/ArduinoCore-avr/blob/master/cores/arduino/Stream.cpp), [Chrome Bluetooth SPP 연결](https://developer.chrome.com/blog/serial-over-bluetooth/).

## 검증

`node tests/serving-bluetooth.test.mjs`: 수량 순서, 0회, 연속 주문의 구분자 잔류 방지, 새 응답 문구와 CRLF·분할 UTF-8, 중복 응답, 전송 오류 검사. 모의 Web Serial/Firebase 브라우저 검사로 화면 전환과 완료 저장·재시도·끊김 복구도 확인합니다. 실제 하드웨어는 연결하지 않았습니다.

시작 응답 대기 제거는 웹의 화면 흐름 변경입니다. 아두이노 스케치 자체의 초음파 센서 대기는 그대로 동작합니다. 웹은 전송을 시작할 때부터 장치에 쓰며, 별도의 시작 명령을 추가하지 않습니다.

## 개별 신호 간 대기

밥 숫자를 쓴 후 300ms 대기하고, 반찬 숫자를 쓴 후 다시 300ms 대기한 다음 국 숫자를 씁니다. 한 문자열로 합쳐 쓰거나 세 쓰기를 동시에 시작하지 않습니다. 마지막 국 전송 후에는 추가 대기 없이 진행 중 화면으로 바꾸고 완료 응답을 기다립니다. 각 전송 시각은 기존 콘솔의 TX_REQUEST / TX_WRITE_OK 로그로 확인할 수 있습니다. 대기 중 연결이 끊기거나 운영이 중지되면 남은 신호를 보내지 않습니다.
