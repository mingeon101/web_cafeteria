# 기존 급식 신청 화면 + 학생 좌석예약

## 무엇을 추가했나요?

첨부하신 원본 HTML·CSS·JavaScript를 변경하지 않고, 닫는 body 태그 바로 앞에 좌석예약 전용 스타일과 스크립트를 추가했습니다. 원본의 학생 조회, 학생증 OCR, 얼굴 인식, 알레르기 표시, 급식 선주문, 운영 중지 기능의 코드를 그대로 보존했습니다.

추가한 기능:

1. 기존 화면에서 학생 조회 → **맞아요**를 누르면 **좌석예약 · 같이 앉기** 버튼 표시
2. 날짜는 한국시간 기준 오늘, 시간대는 등록된 운영 시간표에서 선택
3. 혼자 예약하거나, 같이 앉기 버튼으로 친구의 학년·반·번호를 입력해 초대
4. 상대가 학생 확인을 마친 상태라면 화면 알림과 초대 목록을 실시간 표시
5. 상대가 수락하면 그룹에 참여. **본인 포함 최대 8명**이며, 대기 중인 초대도 정원에 포함
6. 모든 대기 초대에 응답했거나 그룹장이 남은 초대를 취소하면 그룹장이 좌석 선택
7. 같은 테이블의 이어진 좌석 또는 인접한 테이블의 이어진 좌석을 인원수만큼 예약
8. 그룹장과 참여한 친구 모두 자기 자리와 그룹 전체 좌석 확인
9. 초대 거절·취소, 예약 전 그룹 나가기, 그룹장의 전체 예약 취소
10. 중복 그룹 가입·자기 초대·같은 친구 중복 초대·이미 예약된 좌석 재예약 방지

그룹장은 처음 선택한 좌석을 배정받고, 나머지 친구는 학생 UID 순으로 나머지 선택 좌석을 배정받습니다. 예약 확정 결과에 각자의 자리 번호를 표시합니다. 특정 친구에게 특정 좌석을 수동으로 지정하는 기능은 포함하지 않았습니다.

## 적용 파일

**index.html은 원본과 추가 기능을 합친 완성본입니다.** 기존 페이지의 HTML 파일을 이 파일로 교체하되, 기존 파일명과 배포 위치를 유지하세요. 새 기능에 필요한 스타일·스크립트가 모두 포함되어 있으므로 별도 JS 파일을 함께 배포하지 않아도 됩니다.

seat-core.js, seat-addon.js, seat-addon.css는 추가 기능의 검토·수정용 원본입니다. index.html에 이미 포함되어 있으므로 이 파일들을 다시 script/link 태그로 추가하지 마세요. 별도 파일을 수정했다면 index.html의 해당 추가 블록에도 동일한 변경을 반영해야 합니다.

기존 OCR 등에 사용하는 Netlify 함수와 기존 얼굴 모델 파일의 경로는 원본과 같습니다. 완성본을 다른 사이트로 옮길 때는 기존 기능의 서버 함수·리소스도 함께 유지해야 합니다.

## 1. 배치도 준비

앞서 만든 **로그인 없는 독립형 배치도 편집기**에서 테이블과 좌석을 배치해 Firebase에 저장합니다.

읽는 경로: `cafeteriaLayoutEditor/layoutVersions/{버전ID}`

- `reservation` 예약 우선석과 `flex` 전환 가능석은 사전예약 후보가 됩니다.
- `onsite` 현장 우선석은 이 학생 화면에서 예약할 수 없습니다.
- 테이블 간 인접성은 배치 격자 기준으로 판정합니다. 테이블 외곽 간격 1칸 이내이며, 선택한 좌석들의 인접 그래프가 이어져야 합니다. 격자는 실제 거리 단위가 아니므로 실제 식탁 위치에 맞춰 관리자가 배치해야 합니다.

## 2. 급식 시간표 등록

Firebase Console → Realtime Database → 데이터에서 **cafeteriaLayoutEditor/reservationConfig** 경로를 만들고 `예약시간_설정예시.json` 내용을 등록하세요. **해당 경로에서만 가져오기**를 사용하고 DB 루트에 가져오지 마세요.

예시 파일의 12:00~13:00 시간대는 학교의 실제 시간표가 아닙니다. 학교 급식 시간에 맞게 수정 후 등록하세요. 시간표가 없으면 좌석예약은 열리지 않고, 기존 급식 신청은 계속 사용할 수 있습니다.

| 설정 | 의미 |
|---|---|
| enabled | true이면 좌석예약 기능 사용 가능 |
| maxFriends | 7이면 본인 포함 최대 8명. 더 큰 값은 허용하지 않음 |
| minOnsiteSeats | 시간대마다 사전예약으로 채우지 않고 남길 최소 좌석 수. 예시는 0이므로 학교 운영 기준으로 조정 |
| slots | 시간대 ID와 표시 이름·시작·종료 시각. 24시간 HH:mm 형식, 한국시간 기준 |
| layoutVersionId | 선택 사항. 특정 배치도 버전 고정. 생략하면 당일 첫 그룹 생성 전 최신 배치도를 조회 |

동일 날짜의 첫 그룹 생성 시 배치도·시간표·정원을 스냅샷으로 저장합니다. 운영 도중 배치도가 바뀌어 기존 예약 좌석이 사라지지 않게 하기 위한 설계입니다. 이미 예약 데이터가 있는 날의 시간표·배치 변경은 자동으로 반영하지 않습니다. `enabled: false`는 실시간으로 기능을 닫습니다.

## 3. Firebase 읽기·쓰기 권한

추가 코드가 사용하는 경로:

```text
students/                                   기존 학생 조회 자료
cafeteriaLayoutEditor/
  layoutVersions/                           기존 독립형 편집기 배치도
  reservationConfig/                        운영 시간표
cafeteriaSeatReservations/
  days/
    YYYY-MM-DD/
      schemaVersion: 1
      meta/                                 당일 배치도·시간표 스냅샷
      groups/
        그룹ID/
          leaderUid, slotId, status
          members/학생UID/                   참여자
          invites/친구UID/                   pending / accepted / declined 등
          reservation/
            layoutVersionId
            seatIds                         확정 좌석 ID 목록
            assignments/학생UID             개인별 배정 좌석 ID
      memberGroups/학생UID                   현재 참여한 그룹ID
```

학생 자료의 이름·학년·반·번호 필드는 원본과 같은 숫자/문자열 및 한글 필드를 지원합니다. 같은 학년·반·번호의 학생이 둘 이상이면 임의로 골라 초대하지 않고 등록 정보 확인 메시지를 표시합니다.

### 현재 인증 방식과 테스트 규칙

원본은 학년·반·번호 조회로 학생을 선택하며, 서버에서 검증하는 학생 로그인 세션이 없습니다. 이를 그대로 유지했으므로 **클라이언트의 그룹 권한 검사만으로 실제 학생 본인임을 보장할 수는 없습니다.** 화면 버튼을 우회한 직접 DB 요청을 막는 운영용 인증 체계는 포함하지 않았습니다.

`database.rules.demo.fragment.json`은 **가상 학생 데이터로 기능을 확인하는 테스트용 규칙 조각**입니다. 추가 예약 데이터에 로그인 없는 읽기·쓰기를 허용하므로 실제 학생 데이터 서비스의 운영용 규칙으로 그대로 사용하지 마세요. 운영 전에는 검증된 학생 세션과 서버 측 초대·수락·예약 API 또는 이에 대응하는 접근 규칙이 필요합니다. 시간 제한 역시 현재 클라이언트 시각 기반이므로 운영용 서버에서 다시 검증해야 합니다.

테스트 프로젝트에서는 이 파일의 분기를 기존 규칙에 병합하세요. 기존 `students`, `preorders`, 배치도 저장 규칙 전체를 덮어쓰지 마세요. 실제 Firebase 규칙이나 운영 데이터를 이번 작업에서 변경하지 않았습니다.

## 함께 예약할 때의 동작

- 초대는 전송 즉시 Firebase에 저장됩니다. 수락은 초대받은 학생 화면에서 진행합니다.
- 다른 그룹에 이미 가입했거나 예약한 친구는 초대할 수 없습니다.
- 여러 그룹의 초대를 받은 학생이 하나를 수락하면 나머지 대기 초대는 자동 거절됩니다.
- 수락을 기다리는 동안 실제 좌석은 선점하지 않습니다. 그룹장이 확정할 때까지 다른 학생이 예약할 수 있습니다.
- 그룹장이 좌석을 확정하면 당일 데이터 경로의 Firebase 트랜잭션에서 그룹 상태·참여 인원·좌석 중복·현장 최소 좌석 수를 다시 검사합니다. 동시에 같은 자리를 요청하면 먼저 성공한 요청만 예약됩니다.
- 그룹장이 전체 예약을 취소하면 좌석과 그룹 참여 연결을 해제합니다. 친구도 새 그룹에 참여할 수 있습니다.
- 한 학생은 하루에 한 그룹만 참여할 수 있습니다. 다른 시간대로 옮기려면 기존 그룹을 취소하거나 예약 전 그룹에서 나가야 합니다.
- 시작 시각이 지난 시간대에는 새 그룹 생성·초대·수락·좌석예약이 불가능합니다.

## 알림의 범위

이 기능은 **페이지 안 실시간 알림**입니다. 상대방이 같은 페이지에서 본인 학생 확인을 마친 상태이면 초대 알림이 표시됩니다. 페이지를 닫아두었다면 다음 접속 때 학생 확인 후 대기 초대를 볼 수 있습니다. 휴대폰 잠금화면 푸시·문자·이메일 발송은 포함하지 않았습니다.

배식 단말기를 여러 학생이 함께 사용하는 경우 학생 정보가 초기화되면 이전 학생의 알림 구독을 해제하고 좌석예약 창을 닫습니다. 친구 초대를 서로 실시간으로 확인하려면 각자의 기기에서 페이지를 열어두는 방식이 적합합니다.

## 검증

- 추가 블록을 제거하면 첨부 원본 파일과 바이트 단위로 동일함을 검사
- 인원 상한, 중복 초대, 가입 충돌, 인접성, 시간 제한, 예약 경합, 취소 등 핵심 테스트 8개 통과
- 두 브라우저 화면에서 학생 조회 → 친구 초대 → 알림 → 수락 → 좌석예약 → 상대 좌석 확인을 검사
- 서로 다른 그룹의 동일 좌석 동시 요청 시 한 그룹만 예약되는 것을 검사
- 기존 급식 신청 제출과 학생 초기화 흐름을 검사
- 모바일 화면 확인

Firebase는 공유 모의 DB로 테스트했습니다. 실제 프로젝트 연결·보안 규칙 배포·실제 학생에게 알림 전송은 수행하지 않았습니다.
