자동 좌석 안내 + 기존 배식 기능

index.html이 완성본입니다. 추가 기능의 CSS와 JavaScript도 HTML 안에 포함되어 있습니다.
첨부한 원본 HTML은 그대로 두고 마지막에 좌석 연동 기능을 추가했습니다.

학생 확인 후 동작
1. 좌석 예약이 있으면 본인에게 지정된 예약 좌석을 표시합니다.
2. 예약이 없으면 현재 시간대의 빈 좌석을 현장 구역 → 유연 구역 → 예약 구역 순으로 찾고, 구역 안에서는 테이블/좌석 번호순으로 배정합니다. 다른 학생의 예약석과 사용 중인 좌석은 제외합니다.
3. 좌석을 4초간 안내한 다음 기존 배식 절차로 이동합니다. 선주문이 있으면 기존 선주문 자동 처리, 없으면 기존 수량 선택 화면으로 이동합니다.
4. 이미 처리된 선주문은 자동으로 다시 배식하지 않습니다.
5. 만석, 예약 시간 전, 운영 시간 외, 설정 누락, 저장 실패 시 오류를 표시하고 자동 진행을 멈춥니다.

기존 Firebase와 연결
- 배치도: cafeteriaLayoutEditor/layoutVersions
- 예약 시간표: cafeteriaLayoutEditor/reservationConfig
- 날짜별 예약 및 좌석 사용: cafeteriaSeatReservations/days/YYYY-MM-DD
- 선주문: students/학생ID/preorders/YYYY-MM-DD
이전에 만든 배치도/학생 예약 페이지와 같은 Firebase 프로젝트를 사용해야 합니다.
관리자가 예약을 활성화하고 실제 운영 시간표를 설정해야 합니다. 샘플 시간표는 실제 운영 시간에 맞게 수정하세요.
좌석 배정은 날짜별 데이터의 Firebase 트랜잭션으로 처리합니다.

좌석 반납
배식 완료는 식사 완료가 아니므로 그 순간 좌석을 비우지 않습니다.
실제로 자리를 비운 뒤 완료 화면의 '식사 후 좌석 반납'을 누르면 빈자리로 바뀝니다.
퇴장 센서 등은 연결하지 않았으므로 물리적인 퇴장을 자동 감지하지 않습니다.

확인 범위
핵심 로직 테스트 6개와 브라우저 모의 Firebase 연동 테스트를 통과했습니다.
예약 좌석, 순차 배정, 선주문 자동 진행, 수량 선택 후 배식, 중복 선주문 방지, 좌석 반납, 모바일 폭을 확인했습니다.
실제 Firebase 데이터에는 쓰지 않았으며 카메라/손동작 하드웨어는 모의 처리했습니다.
원본의 로그인 및 데이터 접근 구조를 유지했습니다. 실제 공개 운영의 학생 식별과 Firebase 접근 권한은 별도로 구성해야 합니다.
