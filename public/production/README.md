# 급식 준비 현황

배포 후 `/production/`에서 열 수 있습니다. `public/`을 하위 경로로 제공하는 GitHub Pages에서는 `/web_cafeteria/public/production/`입니다. 서비스 바로가기와 관리자 대시보드에도 링크가 있습니다.

- 날짜와 중식·석식을 선택하고 학년별로 필터링합니다. 날짜는 한국 시간 기준입니다.
- `preorders/{YYYY-MM-DD}` 또는 `preorders/{YYYY-MM-DD}__dinner`에 있는 기존 선주문을 실시간으로 읽습니다. 학생별 복제 기록을 다시 합치지 않습니다.
- `pending`, `fulfilled`를 포함합니다. 상태가 없는 이전 기록은 대기로 취급합니다. 취소, 0회, 수량·날짜·상태가 잘못된 기록은 제외하고 건수를 표시합니다.
- 메뉴별 숫자는 신청 학생 수와 별도로 **배식 횟수**입니다. 완료된 주문도 전체 준비량에 포함합니다. 실제 배식 수정값 `actual`은 준비 전 수요와 혼합하지 않습니다.
- 예상 준비 횟수 = 올림((선주문 횟수 + 추가 현장 예상 인원) × (1 + 여유분 / 100)). 현장 학생은 메뉴별 1회로 가정합니다. 학년 필터를 쓰면 현장 인원도 해당 학년에 맞게 입력해야 합니다.
- 예상 무게는 조리 후 배식 중량 기준이며 식재료 발주량이 아닙니다. 기본값은 밥 225g, 국 225g, 반찬 110g이고 수정할 수 있습니다. 현장 인원·여유분은 처음에 0으로 시작합니다.
- 중량과 여유분은 브라우저에 기억합니다. 현장 인원은 날짜·중식/석식·학년별로 분리해 기억합니다. Firebase에는 설정, 예상치, 학생 기록을 쓰지 않습니다.
- 신청 시 저장된 `menuSnapshot`을 우선 사용합니다. 서로 다른 메뉴가 있으면 표시하고, 과거·미래 기록에 날짜가 다른 현재 메뉴를 붙이지 않습니다.
- CSV와 인쇄를 지원합니다. 연결이 끊기면 마지막 조회임을 표시하며 CSV·인쇄를 비활성화합니다. 조회 오류를 주문 0건으로 표시하지 않습니다.
- 학생 이름, 고유 ID, 이메일, 얼굴 정보는 화면 및 CSV에 포함하지 않습니다. 기존 Firebase 읽기 권한을 그대로 사용하며 보안 규칙을 변경하지 않습니다.

핵심 로직 확인: `node --test tests/production-core.test.mjs`
