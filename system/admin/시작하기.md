# 로그인 없는 독립형 급식실 배치도 편집기

기존 관리자 페이지와 연결하지 않고 이 폴더만으로 사용하는 별도 화면입니다. 로그인 창, Firebase Authentication, 관리자 UID 조회를 모두 제거했습니다.

## 실행 방법

1. 이 폴더 전체를 정적 웹 호스팅에 업로드합니다. 별도 사이트의 루트 폴더로 사용해도 됩니다.
2. 사이트 주소로 접속하면 바로 테이블 배치·편집·JSON 가져오기 및 내보내기를 사용할 수 있습니다.
3. Firebase 저장과 조회를 위해 아래 데이터베이스 규칙을 설정합니다.

JavaScript 모듈을 사용하므로 index.html을 더블클릭하는 file:// 실행 대신 웹 서버로 열어주세요. index.html과 함께 모든 .mjs 파일을 업로드해야 합니다.

## Firebase 연결

- firebase-config.mjs에는 기존에 제공받은 Firebase 프로젝트 설정을 넣어두었습니다.
- 완전히 별도 Firebase 프로젝트로 운영하려면 이 파일의 설정값을 새 프로젝트의 웹 앱 설정으로 교체하세요. Authentication 설정은 필요하지 않습니다.
- 저장 경로는 기존 관리자와 분리한 **cafeteriaLayoutEditor/layoutVersions/{버전ID}**입니다. 기존 cafeteria/layoutVersions 배치도는 이 화면 목록에 나오지 않습니다. 필요하면 이전 편집기에서 JSON을 내보내 새 화면으로 가져오세요.
- 데이터에는 배치도 이름, 가로·세로 크기, 테이블 위치와 방향, 좌석 번호와 좌표, 기본 구역, 총 좌석 수, 서버 저장 시간을 기록합니다. 사용자 식별값은 기록하지 않습니다.

## 데이터베이스 규칙

Firebase Console → Realtime Database → Rules에서 database.rules.fragment.json의 cafeteriaLayoutEditor 분기를 기존 rules 아래에 병합하세요. 별도 프로젝트의 기본 거부 규칙에 추가하는 방식으로도 사용할 수 있습니다. 기존 메뉴·학생 데이터 규칙을 이 파일 전체로 교체하지 마세요.

이 규칙은 배치도 경로에 한해 **인증 없이 읽기와 새 버전 추가를 허용**합니다. 따라서 사이트나 데이터베이스 주소를 아는 사람은 배치도를 조회하거나 새 버전을 추가할 수 있습니다. 기존 버전 수정·삭제는 이 분기에서 허용하지 않습니다. 상위 경로가 쓰기를 허용하면 하위 제한보다 우선하므로 상위 규칙을 확인하세요.

실제 Firebase 규칙은 이번 작업에서 변경하지 않았습니다. 기존 로그인 필수 규칙이 남아 있으면 저장·조회가 권한 오류로 실패하므로 위 설정을 적용해야 합니다.

## 포함 기능

- 2·4·6·8인 테이블 추가, 드래그·방향키 이동, 회전, 삭제, 실행 취소
- 테이블 이름·좌석 수·위치 설정
- 예약 우선 / 현장 우선 / 전환 가능 기본 구역
- 테이블 겹침과 경계 이탈 검사
- JSON 가져오기·내보내기
- 로그인 없는 Firebase 새 버전 저장 및 최근 20개 버전 조회·불러오기

테이블 이동·회전 시 좌석 ID를 유지합니다. 저장 시마다 새 버전을 만들므로 이전 배치도를 덮어쓰지 않습니다. 격자는 편집 단위이며 실제 길이·통로 폭이 아닙니다. 시간대별 예약 배정, 학생 체크인, 자동 퇴장 감지는 다음 단계 기능으로 포함하지 않았습니다.

## 파일 구성

- index.html: 독립형 화면
- editor.mjs: 편집 및 저장 동작
- layout-core.mjs: 좌석 생성·배치 검증
- firebase-store.mjs: 인증 없는 Firebase 저장·조회
- firebase-config.mjs: 프로젝트 연결값
- database.rules.fragment.json: 배치도 전용 규칙

브라우저 편집과 모의 Firebase 저장·조회 흐름을 테스트했습니다. 실제 프로젝트에 대한 저장·규칙 적용 테스트는 수행하지 않았습니다.
